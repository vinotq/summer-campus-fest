# 00. Обзор системы

## Назначение
«Сириус.Капча» — станция активности на КампусФесте. Игрок проходит набор капч (различных типов) за ограниченное время, получает очки в зависимости от скорости и правильности. Параллельно работают админская часть (редактор вопросов, список игроков) и публичный дашборд топ-10.

## Стек
- **Backend:** Node.js (LTS 20+), Fastify, Socket.IO, better-sqlite3, sharp (обработка изображений), @fastify/multipart, @fastify/cookie, @fastify/static.
- **Frontend:** React + Vite (JavaScript, без TS), TailwindCSS, Zustand, socket.io-client, react-router. (Детали фронта — отдельной командой.)
- **БД:** SQLite (один файл, WAL-режим).
- **Деплой:** Docker Compose: сервис `app` (Node) + `nginx` (reverse-proxy и отдача статики фронта).
- **OS-цель:** Linux VPS 1 vCPU / 2 GB RAM / 10 GB.

## Ограничения и допущения
- ~30 одновременных игроков в пике.
- Один общий QR-код на стенде, на странице — обязательный ввод **Фамилия Имя**.
- Защита «не пройти дважды» — мягкая (localStorage-флаг + ручной контроль админом по списку). Жёсткой привязки к личности нет.
- Один админ. Один логин/пароль из `.env`.

## Сетевая схема (prod)

```
              ┌──────────────────────────────────────┐
   Internet → │  nginx (80/443)                      │
              │   ├─ /            → web (static)     │
              │   ├─ /api/*       → app:3000         │
              │   ├─ /socket.io/* → app:3000 (ws)    │
              │   └─ /uploads/*   → /data/uploads    │
              └──────────────────────────────────────┘
                              │
                              ▼
                    ┌──────────────────┐
                    │ app (Fastify+IO) │
                    │  better-sqlite3  │
                    └────────┬─────────┘
                             ▼
                        /data (volume)
```

## Принципиальные решения
1. **better-sqlite3 синхронный** — это нормально под 30 пользователей и упрощает код. WAL включаем при старте.
2. **Один процесс Node** — без кластера. Socket.IO in-memory adapter (для кластера нужен был бы Redis).
3. **Хранение картинок/аудио на диске**, в БД — только относительные пути.
4. **Авторизация админа:** httpOnly cookie с подписанным токеном (HMAC).
5. **Сессия игрока:** httpOnly cookie с подписанным `sessionId`. Браузер не должен иметь возможность «начать заново» без очистки cookie.
