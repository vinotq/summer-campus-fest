# 10. Деплой

Стенд живёт на `captcha.sirius-campus.ru`, VPS 153.80.184.234, каталог
`/opt/captcha`. Пошаговая первичная настройка машины — в
[`deploy/SETUP.md`](../deploy/SETUP.md); здесь только устройство.

## Схема

```
браузер
   │ https
хостовой nginx (1.18, на машине, общий с соседними проектами)
   │  vhost captcha.sirius-campus.ru, TLS, лимиты запросов
   │  proxy_pass -> 127.0.0.1:8084
web  (nginx:alpine в контейнере)
   │  раздаёт собранный фронт и /uploads/
   │  /api/ и /socket.io/ -> app:3000
app  (node:20-alpine)
   │  Fastify + Socket.IO
   └─ /data  <- ./data на хосте (db.sqlite, uploads/)
```

Два уровня nginx не избыточность: хостовой держит TLS и делит машину между
пятью проектами, контейнерный едет в образе вместе со сборкой фронта. Так
«на диске новый билд, а отдаётся старый» стать не может — они один слой.

## Структура

```
campus-fest-summer/
├── docker-compose.yml     # app + web
├── Dockerfile.server      # app: Fastify
├── Dockerfile.web         # сборка Vite -> nginx:alpine
├── nginx.conf             # контейнерный nginx
├── deploy/
│   ├── SETUP.md           # первичная настройка машины
│   ├── push.sh            # выкладка с ноутбука
│   ├── remote-deploy.sh   # удалённая часть, исполняется на VPS
│   ├── backup-db.sh       # снимок базы (WAL, через .backup)
│   ├── reset-players.sh   # обнуление таблицы лидеров между фестами
│   ├── host-nginx.conf    # vhost :80, ACME + редирект
│   └── host-nginx-ssl.conf# vhost :443, подключается после certbot
├── .env                   # на сервере, не в git
└── data/                  # не в git
    ├── db.sqlite
    └── uploads/
```

## Выкладка

```bash
./deploy/push.sh
```

Скрипт делает rsync каталога в `/opt/captcha` (исключая `.env` и `data/`)
и запускает там `deploy/remote-deploy.sh`. Тег образа — хеш текущего
коммита; он же уезжает в `APP_VERSION` и отдаётся в `/api/health`.

`remote-deploy.sh` по порядку:

1. проверяет, что `.env` есть и в нём заданы `ADMIN_LOGIN`,
   `ADMIN_PASSWORD_HASH`, `COOKIE_SECRET`;
2. снимает бэкап базы (пропускается на первом деплое);
3. чистит слои старше недели — на диске 13 ГБ свободного;
4. собирает образы на месте и поднимает контейнеры;
5. перечитывает конфигурацию контейнерного nginx: он резолвит адрес `app`
   один раз при старте, и пересозданный контейнер иначе даёт 502 при живых
   процессах;
6. раскладывает vhost хостового nginx, подключая TLS только при наличии
   `fullchain.pem` — иначе `nginx -t` упал бы и сломал reload **всем** сайтам
   машины;
7. проверяет, что контейнеры подняты из образов этого деплоя;
8. проверяет, что домен отдаёт `"version"` этой сборки.

Последние два шага — не формальность. «Деплой зелёный» и «на сайте новая
версия» разные утверждения: контейнер может не пересоздаться, домен может
смотреть на другой стек, nginx — проксировать на чужой порт.

GitHub Actions (`.github/workflows/deploy.yml`) делает ровно то же самое,
но выключен: Actions на приватных репозиториях недоступны из-за биллинга.

## Сборка на VPS, а не в CI

Двух ядер и 2 ГБ свободной памяти хватает с запасом: Vite отдаёт бандл
на 400 КБ за секунды. Это не Next.js соседнего «Старта», чей пик сборки
в полтора гигабайта потребовал бы внешнего раннера.

## Порты

`8080` занят `sirius-eviction`, `8082` — «Стартом», `8083` — ЛКП.
Наш контейнерный nginx слушает `127.0.0.1:8084`. Наружу не публикуется
ничего: `app` доступен только по докер-сети.

## Бэкапы

`deploy/backup-db.sh` вызывается перед каждой выкладкой и годится для
crontab. Копия снимается через `sqlite3 .backup`, а не `cp`: база работает
в режиме WAL, и простая копия тихо теряет последние ответы игроков.
Снимки в `/var/backups/captcha`, хранятся 14 дней.

## Пароль администратора

```bash
cd /opt/captcha
docker compose run --rm app node /app/server/scripts/hash-password.js 'пароль'
# вставить результат в .env как ADMIN_PASSWORD_HASH
docker compose up -d app
```

Формат `scrypt:salt:key` — через двоеточие, не через `$`: знак доллара
docker compose съест как подстановку переменной.

## Наблюдение

- `docker compose logs -f app` — ход игры и ошибки;
- `GET /api/health` → `{ ok, uptime, version }`, им же пользуется деплой;
- `docker stats` во время феста: у `app` потолок 512 МБ, у `web` — 64 МБ.
